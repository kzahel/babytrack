# 006: M2 responsive web client

Status: first local preview slice implemented; shared caregiver flow open.
The [MVP plan](../mvp-plan.md#milestones) owns scope. The
[web client topic](../topics/web-client.md) owns route and storage decisions;
the [Family contract](../topics/family-sharing-and-trust.md) owns access
semantics. This tactical owns web delivery and gate evidence.

## Goal

Give a caregiver a responsive accountless browser client that uses the Rust
wasm core for local tracking, verified encrypted sharing, and recovery. A
browser profile is a device. The relay and web app use one canonical origin.
No server route interprets or decrypts Family records.

## Slices

1. [x] Create a responsive Today, History, and Family shell with phone bottom
   navigation and a tablet/desktop rail. Create local Families and children,
   log diaper, whole-millilitre bottle, and notes through Rust wasm, and show
   durable history after reload. Keep copy in a translation-ready catalog.
   The Playwright smoke covers a narrow viewport, desktop switch, two-Family
   isolation, and reload. Browser assets build to a static directory.
2. [ ] Add complete local capture/edit coverage and file export/restore using
   the shared Rust model. Match Android's clear Family/child target and
   pending-work behavior; check large text, dark mode, RTL, and keyboard use.
3. [ ] Connect first and later device enrollment to the existing IndexedDB
   invitation/authority adapters. Show verified claim, proof, grant, and
   history-loading stages; never show a keyless Family as ready. Exercise a
   real relay with an Android and browser client, delayed wakes, offline
   edits, and restart.
4. [ ] Handle rotation, removal, and private-copy recovery in web UI. Add
   backup and an optional local lock only after the basic flow is coherent.
5. [ ] Run the named independent web trust-boundary review before real-data
   use. Check served-code trust, CSP, same-origin routing, browser credential
   storage, and target isolation. Retain the current disposable-data preview
   scope until that gate passes.

## Early preview deployment

An opt-in disposable-data preview may be hosted before M5 to test navigation
and interoperability. The deployment host, DNS, Caddy routes, service unit,
and scripts live in private infrastructure configuration outside this repo.
The portable source tree contains only the build inputs. Publishing, hosted
service operations, and store release remain M5 work.

Completion: Android and web can independently enroll as devices in the same
Family, converge after offline work, and recover clearly after removal or
browser storage loss; the M2 security gate and CI flow pass.
