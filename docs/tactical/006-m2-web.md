## Goal

Give a caregiver a responsive accountless browser client that uses the Rust
wasm core for local tracking, verified encrypted sharing, and recovery. A
browser profile is a device. The relay and web app use one canonical origin.
No server route interprets or decrypts Family records.

## Trust-boundary review at cbc3034

The independent Daybreak Blue, high-thinking review inspected committed
`cbc30342a0629ee2aa0450a517389de8ffa92657` in a clean detached checkout.
Yep Anywhere session `01a0ed40-fb69-7fd0-9285-a71112d68a2f` ended with
**FAIL** for the bounded native-managed browser gate. It modeled an honest
ordered relay, an authorized hostile device, compromised relay storage, and
a relay that withholds or forks history. The reviewer ran Rust core, server,
and CLI tests; it did not run Playwright in its read-only checkout.

- Link opening consumed a one-use claim before confirmation. Fixed in
  `05b7354`; the real-relay UI case asserts no control POST before Join.
- A persisted stale claim/proof could loop on a moved control head (FS76),
  and terminal invitation status was not verified (FS77). Browser enrollment
  now recovers exact candidates from verified controls, archives candidates
  before refresh with unchanged device secrets, and verifies/persists signed
  terminal status. Real-relay UI tests race an unrelated control into a claim,
  lose a committed claim response, and cancel an invitation; the browser byte
  smoke checks the status vector.
- A reloaded outbox could briefly report up to date and a withheld relay
  response could leave sync hanging. The UI now derives pending state from
  durable storage and transport calls time out. Real-relay reload checks it.
- A cross-database removal copy could miss a second tab's concurrent edit.
  The shared outbox and verified removal now serialize on one IndexedDB
  object store; public append and outbox rebase also check the freeze. A stale
  tab's save redirects into the same independent local Family, retaining the
  action and telling the person where it went. The copy mapping itself
  remains retryable in the local database.
- A bounded first download could mark a keyless/partial Family ready and
  export a false complete backup (FS27, FS43). Admission now waits for the
  full visible log; completeness is durable and exposed in backup copy.

Hosted code and browser profile compromise remain accepted browser trust
limits. Deployed CSP and security headers are checked below. The current
preview remains disposable-data only. Request one focused recheck of the
access and data-retention blockers; do not infer a gate pass from these

### Focused recheck at ce3189b
